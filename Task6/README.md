# Задание 6. Автоматическое ежедневное обновление базы знаний

## Источник новых документов

Источник - локальная папка [incoming_docs/](incoming_docs/). Она симулирует
любой реальный источник (S3-бакет, Confluence-экспорт, отдельный
Git-репозиторий с документацией): подхват новых файлов происходит по факту
их появления или изменения в этой папке, без ручного вмешательства. Чтобы
переключиться на реальный источник, достаточно заменить в
[update_index.py](update_index.py) функцию `scan_source()` на загрузку
файлов из нужного хранилища - остальной пайплайн (чанкинг, эмбеддинги,
обновление индекса, логирование) не меняется.

## Скрипт обновления - update_index.py

При каждом запуске [update_index.py](update_index.py):

1. Сканирует `incoming_docs/*.md` и сравнивает SHA-256 хэш каждого файла с
   сохранённым в [manifest.json](manifest.json) - так находятся новые,
   изменённые и удалённые документы.
2. Разбивает новые/изменённые документы на чанки тем же способом, что и в
   Задании 2/3 - `RecursiveCharacterTextSplitter`, `chunk_size=1000`,
   `chunk_overlap=150`.
3. Генерирует эмбеддинги той же моделью `BAAI/bge-m3` (выбрана в Задании 1,
   применена в Задании 3).
4. Обновляет векторный индекс FAISS в [index/](index/): добавляет чанки
   новых документов, удаляет чанки устаревшей версии изменённых документов
   и чанки удалённых документов (опциональное удаление реализовано, а не
   только добавление).
5. Логирует процесс в [logs/update.log](logs/update.log) (человекочитаемая
   строка на запуск) и [logs/update_log.jsonl](logs/update_log.jsonl)
   (структурированная запись: время начала/конца, число новых/изменённых/
   удалённых файлов, число добавленных/удалённых чанков, итоговый размер
   индекса, список ошибок).

При первом запуске рабочий индекс `index/` инициализируется как копия
готового индекса `Task3/faiss_index` (45 документов, 393 чанка из
Задания 2/3), а `incoming_docs/` обрабатывается как источник последующих
обновлений - это позволяет проверить механизм обновления без пересчёта всей
базы знаний с нуля.

Файлы, которые не удалось обработать (например, повреждённая кодировка),
не прерывают весь запуск: ошибка по конкретному файлу попадает в список
`errors`, остальные файлы обрабатываются как обычно.

## Периодический запуск

Запуск - обёртка [run_update.sh](run_update.sh):

- активирует виртуальное окружение проекта (`.venv`) и вызывает
  `update_index.py`;
- при ошибке повторяет запуск (до 2 попыток), каждая попытка попадает в
  общий лог;
- возвращает код завершения 0 при успехе и 1, если после всех попыток
  остались ошибки.

Планировщик - `cron` (Linux/macOS). Задача регистрируется командой
`crontab -e` строкой из файла [crontab.txt](crontab.txt) (путь нужно
заменить на реальный путь к репозиторию на сервере):

```
0 6 * * * /path/to/architecture-pro-ai-rag/Task6/run_update.sh >> /path/to/architecture-pro-ai-rag/Task6/logs/cron_stdout.log 2>&1
```

Установка: `crontab Task6/crontab.txt` (после подстановки реального пути).

- Частота: ежедневно в 6:00 по времени сервера.
- При ошибке: `run_update.sh` делает повторную попытку (см. выше); итоговая
  ошибка фиксируется в `logs/update.log` и `logs/update_log.jsonl`, а
  stdout/stderr самого cron дополнительно попадает в `logs/cron_stdout.log`.
  Ненулевой код завершения скрипта позволяет системе мониторинга (например,
  алертам по cron-джобе) заметить сбой отдельно от анализа логов.

## Проверка работы

Обновление проверено вручную полным циклом (см.
[logs/update.log](logs/update.log) и [logs/update_log.jsonl](logs/update_log.jsonl)):

1. Первый запуск на пустом `incoming_docs/` - индекс инициализирован копией
   из Task3, `index size 393`.
2. Добавлен новый документ `quantum_relay_stations.md` - `1 files added,
   1 chunks added`, размер индекса выросла до 394.
3. Повторный запуск без изменений - `0 files added, 0 chunks added`
   (идемпотентность).
4. Документ изменён (добавлен раздел) - старый чанк удалён, новый добавлен:
   `1 chunks added, 1 chunks removed`.
5. Документ удалён из `incoming_docs/` - его чанк удалён из индекса:
   `0 files added, 1 chunks removed`, размер вернулся к 393.
6. Добавлены один валидный и один повреждённый (невалидный UTF-8) файл -
   валидный обработан и добавлен в индекс, повреждённый зафиксирован в
   `errors` без остановки всего обновления.

Пример строки итогового лога:

```
index updated at 2026-07-13, 1 files added, 1 chunks added, 0 chunks removed, index size 394, 0 errors
```

Финальное состояние репозитория: `incoming_docs/` содержит демонстрационный
документ `quantum_relay_stations.md`, `index/` и `manifest.json` отражают
его учёт, `logs/` содержит полную историю проверки из шести запусков выше.
